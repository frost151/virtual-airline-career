# Virtual Airline Career — контекст проекта

Соло-карьера виртуальной авиакомпании для **MSFS 2024**. Desktop-приложение: Electron + React + TypeScript, локальная база SQLite (встроенный `node:sqlite`, без нативных модулей). Код пишет Claude, пользователь принимает решения по дизайну: сначала предлагаем вариант, пользователь правит или соглашается.

## Решения пользователя (не менять без его согласия)

- **Только MSFS 2024.** X-Plane и P3D не предлагать. Фичи, специфичные для MSFS, — приветствуются.
- **Интерфейс только на русском.** Исключение: **названия авиакомпаний — оригинальные** (Aeroflot, Lufthansa, Emirates), без перевода, с логотипами.
- **Аддоны пользователя** (под них профили трекера): все Fenix (A319/A320/A321), все PMDG кроме DC-6 (737, 777), Cessna Citation X, iniBuilds A350 и A380.
- **Авиакомпании реальные**: 84 штуки (срез на старт мира), включая грузовые (Россия, Китай, UPS, DHL, Cargolux). Новые компании **никогда не появляются**.
- **Время мира = реальное UTC**, мир стартует в момент создания профиля. Пока программа закрыта, мир досчитывается при запуске, после этого показывается «Пока вас не было».
- **Режим пилота:** рейсы по реальному расписанию. Опоздание больше 15 минут → игрок выбирает причину задержки (коды IATA + «SC — сбой симулятора»). Начать рейс в MSFS можно не раньше чем за 2 часа до вылета.
- **Звания:** повышение **только по налёту** (10 / 60 / 200 / 500 ч), без требований по числу полётов и оценке. Множители зарплаты: 1 / 1,8 / 3 / 4,2 / **6** (инструктору ещё нужен курс TRI). Ставка стажёра — $70 за блок-час на A320/737, плюс **оклад** $1 500 × множитель звания в месяц.
- **Игровой множитель заработка** ×1/×2/×5/×10 в настройках. Цены он не меняет.
- **VIP-чартеры:** истории заказов, **вымышленные политики на реальных должностях**, кабинет министров каждой страны сохраняется в профиле, записная книжка клиентов. Самолёты — Citation X, а ACJ319/BBJ — только командирам.
- **Личная жизнь:**
  - размер семьи задаётся при создании профиля;
  - **усталость снимается в основном платным отдыхом**, рейсы недоступны при усталости ≥ 85;
  - налоги — по стране базы;
  - большой автопарк, обязательно российские марки (Lada, УАЗ, Москвич, Aurus); клик по машине показывает фото из Википедии.
- **Банкротства:** национальных перевозчиков спасает государство. Частная компания теряет престиж и начинает заново с 1 самолёта и 1 маршрута, об этом выходит новость. Если это работодатель пилота, пилот теряет работу.
- **Средний тариф рейса показывается пилоту.**
- **Режим читера** (включается в настройках): деньги, налёт, усталость, здоровье, медкомиссия, репутация, допуски, телепорт. В шапке метка «ЧИТ».

## План этапов

1. Данные мира — **готово**
2. Трекер полётов — **готово**, но **не проверено на реальном MSFS** (см. ниже)
3. Режим пилота — **готово**
4. Время и макроэкономика — **готово**
5. Личная жизнь — **готово** (первая версия)
6. Экономика авиакомпаний и конкуренты — **готово** (первая версия)
7. Режим владельца — **готово** (первая версия). Части:
   1. доли 10/25/51% в существующих компаниях (`src/main/airlines/stakes.ts`, таблица `stakes`) — **готово**;
   2. своя компания (`src/main/airlines/player.ts`, таблица `player_airline`; при открытии профиля регистрируется в `airlines`, `playerAirlineIds`) — **готово**;
   3. управление при 51% (`src/main/airlines/manage.ts`, экраны «Флот», «Маршруты», «Финансы») — **готово**. Поля управления живут в `AirlineState` (`autopilot`, `fareMult`, `owned`, `ceoSalary`, `payout`, `listed`; `deliveries` — устаревшее, самолёты теперь приходят сразу); у своей компании заместители по умолчанию сняты, у купленной — стоят. Расписание не может требовать больше блок-часов, чем даёт флот (`planBlockHours`);
   4. персонал (экран «Персонал», `AirlineState.staff`, расчёт в `computeMonth`/`staffMonth` в sim.ts) — **готово**. Норма 90 блок-ч в месяц на человека (решение пользователя); при полном штате оклады ≈ прежней оплате по налёту, поэтому калибровка не сдвигается. Нехватка → доля рейсов отменяется (`last.cancelled`) и падает репутация; зарплата влияет на текучку, сервис — на расходы и репутацию;
   5. полёты CEO (`src/main/airlines/ceo.ts`, `ceoOf` в career.ts) — **готово**. Основатель работает в своей компании (`employer_id` = её ICAO, база — база компании): расписание, брони и трекер общие с пилотом. Оплата — 10% прибыли рейса по итогам прошлого месяца (у маршрутов без итогов — прогноз `projectAirline` на копии рынка), её платит компания и экономит на одном пилоте. Звание всегда CEO, повышений, оклада пилота и увольнения нет;
   6. банкротство и IPO — **готово**. Без поручительства доля сгорает, CEO теряет работу, компания живёт дальше под ИИ (`PlayerAirline.active = false`), можно основать новую. С поручительством банк взыскивает 60% долга: со счёта, остаток — личный кредит `guarantee` (12% годовых, 10 лет). Пока компания в долгах (`distress`) — новость каждый месяц, можно вложить личные деньги (`injectCapital`). IPO (`goPublic`): 10/25/49% после 3 месяцев отчётности и прибыли, деньги — компании, комиссия 7%.

   Числа по умолчанию: надбавка за пакет 10% (за контрольный 30%), при продаже контрольного +15%, комиссия 2%.

## Открытые вопросы и долги

- **Личный кабинет** (`screens/PilotProfile.tsx`) — готово: фото (в `profile.photo`), погоны по званию (у CEO — свои), семья, дом, гараж с фото из Википедии, допуски, доли. Дальнейшие пожелания пользователя — сюда.

- **Проверка трекера на MSFS 2024** (у пользователя тогда не было симулятора):
  - работа `MsfsSource` (`node-simconnect`, Protocol.KittyHawk);
  - **Подтверждено 2026-10-24** (MSFS 2024 «SunRise» 12.2, Fenix A319): подключение по KittyHawk работает; `PLANE PITCH DEGREES` при поднятом носе отрицательный; `PLANE TOUCHDOWN NORMAL VELOCITY` положительный, в ft/s; `Pause_EX1` приходит (на паузе флаги 4, без паузы 0); `TITLE` = «FenixA319 CFM WF SD», `ATC MODEL` = «ATCCOM.AC_MODEL A319.0.text». Профиль Fenix проверен (`verified: true`), положения переключателей записаны в его `notes`. PMDG 737 проверен: стандартные LIGHT-переменные работают (LED и галоген), SDK не нужен. В TITLE у PMDG нет «PMDG», поэтому самолёт опознаётся ещё и по пути к aircraft.cfg (системное состояние `AircraftLoaded`). Осталось проверить PMDG 777, A350, A380 и Citation X;
  - все профили в `data/aircraft-profiles.json` имеют `verified: false`: имена L-переменных Fenix — догадки, PMDG может понадобиться SDK (`EnableDataBroadcast=1`). Пока профиль не проверен, правила по свету для него отключены, чтобы не было ложных штрафов.
  - Проверять на экране «Проверка симулятора» (`/sim-check`, кнопка на «Активном полёте»). Там автоматические проверки тангажа, паузы и касания, свет, пробные L-переменные и ошибки SimConnect. Кнопка «Копировать отчёт» копирует JSON, пользователь присылает его Claude. По итогам ставить `verified: true`.
- **Полёты на своём самолёте** (Cessna, SR22 и т.д. из «Личной жизни») в трекере пока не учитываются отдельно — сделать вместе с проверкой трекера.
- **Режим владельца — доходы владельца** (предложено, пользователь отложил до этапа 7):
  - раздельные кошельки компании и владельца;
  - зарплата CEO, квартальные дивиденды по доле, продажа доли / IPO;
  - личное поручительство по кредитам;
  - пилотский капитал как стартовый для своей компании.
  - **Решено:** стать владельцем можно двумя путями: купить долю существующей компании или основать свою на пилотский капитал (это единственное исключение из правила «новые компании не появляются»). В существующей компании игрок выбирает долю 10/25/51%: с 51% у него управление, с 10 или 25% только дивиденды и место в совете. После банкротства без поручительства доля сгорает, игрок продолжает карьеру пилотом.
  - **Решено (этап 7):**
    - владелец — это **роль**, а не режим профиля: любой пилот может купить долю или основать компанию. Выбор «Владелец» при создании профиля сразу ведёт к основанию или покупке;
    - управление с 51%: **стратегия и персонал**. Стратегия — флот, маршруты и частоты, тарифы, кредиты, зарплата CEO, дивиденды. Персонал — найм пилотов и бортпроводников, уровень зарплат и сервиса, они влияют на репутацию и сбои;
    - в **национальных перевозчиках** игрок может купить не больше 25%: контроль остаётся у государства;
    - профиль «Владелец» при создании выбирает **стартовый капитал**: $2 / 5 / 20 / 100 млн;
    - основав свою компанию, пилот **увольняется** от работодателя и становится CEO;
    - владелец **летает рейсами своей компании**. Звание у него всегда одно — **CEO** (генеральный директор и владелец), налёт на звание не влияет. Компания экономит на экипаже. За рейс владелец получает **процент от прибыли рейса**, отдельно от зарплаты CEO.
- **Названия городов** в историях и расписании на английском (из OurAirports) — можно добавить русские для крупных.

## Устройство кода

- `src/main` — main-процесс:
  - `tracker/` — трекер: фазы, правила, посадка;
  - `sim/` — `MsfsSource`, демо-полёт, профили аддонов;
  - `career/` — карьера, расписание, чартеры, SimBrief;
  - `economy/` — часы мира, макроэкономика;
  - `lifestyle/` — личная жизнь;
  - `airlines/` — экономика авиакомпаний, биржа;
  - `cheats.ts`.
- `src/shared` — типы и чистые правила, общие для main и интерфейса.
- `src/renderer` — интерфейс (React + Mantine), экраны в `src/renderer/src/screens`.
- `data/` — данные мира (JSON, правятся вручную). После правок: `npm run data:validate`.
- **Стиль кода:** без точек с запятой, одинарные кавычки, строки до ~130 символов. Конфига Prettier нет и старый код им не форматирован — **не запускать Prettier по существующим файлам** (с настройками по умолчанию он перепишет весь файл). Для новых файлов можно: `npx prettier --no-semi --single-quote --print-width 130 --trailing-comma none --write <файл>`.
- **Миграции БД** — массив `MIGRATIONS` в `src/main/db.ts`. Новые **только дописываются в конец**.
- **Детерминизм:** случайность только через `seededRng` (`src/shared/random.ts`) с зерном мира — повторный досчёт даёт тот же результат.
- **Калибровка экономики авиакомпаний:** `CALIBRATE=1 npx vitest run src/main/airlines/calibrate.test.ts` (по `CAL_DETAIL=AFL,IGO` — структура расходов). Цели: средняя маржа около 7%, загрузка около 80%, лоукостеры прибыльнее сетевых. В данных только часть реальной сети, поэтому стоимость флота берётся только за самолёты, нужные смоделированной сети. Расходы авиакомпаний на экипажи (`AIRLINE_PILOT_RATE`) **не связаны** с зарплатой игрока.

## Запуск на новом компьютере

```
git clone https://github.com/frost151/virtual-airline-career.git
cd virtual-airline-career
npm install          # npm 11: скрипты electron и esbuild разрешены в package.json (allowScripts)
npm run dev          # разработка
npx vitest run       # тесты
npx tsc --noEmit     # проверка типов
```

Нужен **Node 22.16+** (лучше 24): встроенный `node:sqlite`. Сохранения профилей лежат в `%APPDATA%\Virtual Airline Career\profiles` и в репозиторий не попадают — на новый компьютер их можно перенести вручную.

**Подводный камень:** если запускать Electron из процесса VS Code / Claude Code, там выставлена переменная `ELECTRON_RUN_AS_NODE=1`, и Electron стартует как обычный Node (`app` будет undefined). Перед запуском её нужно удалить: `Remove-Item Env:ELECTRON_RUN_AS_NODE`.

**Git:** имя и почта автора заданы локально в репозитории (`frost151`, `a.somok15@gmail.com`); на новом компьютере их нужно задать заново: `git config user.name …` / `git config user.email …`. Коммиты и push — только по просьбе пользователя.
